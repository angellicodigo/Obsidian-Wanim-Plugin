## 2. Logic Chain

1. **Clean Directory Scaffolding & Scope Boundary**:
   - *Observation*: The task explicitly mandates creating `C:\Users\angel\Notes\.obsidian\plugins\Obsidian Wanim Plugin\` while leaving `obsidian-manim-plugin` strictly read-only and untouched.
   - *Logic*: All manifest, configuration, code, and script files were authored exclusively inside `Obsidian Wanim Plugin`. A baseline SHA-256 hash snapshot of all 26 non-ignored files in `obsidian-manim-plugin` was taken and verified both before and after installation and build, confirming zero writes to the reference directory.

2. **Dependency Resolution & Peer Dependency Accommodation**:
   - *Observation*: `obsidian@1.14.4` specifies peer dependencies on `@codemirror/state: 6.7.6` and `@codemirror/view: 6.43.13`. Exact pinning of older subversions caused npm ERESOLVE conflicts.
   - *Logic*: Using compatible semver ranges (`"@codemirror/state": "^6.5.0"`, `"@codemirror/view": "^6.38.6"`) allowed npm to resolve both Obsidian's peer requirements and `@replit/codemirror-vim` without dependency duplication or `--legacy-peer-deps` workarounds, producing a clean `package-lock.json` with 0 vulnerabilities.

3. **Offline In-Memory RapydScript Bundling**:
   - *Observation*: `@wanimjs/wanim` relies on `globalThis.RapydScript.compile` for Python-to-JS translation, but standard Node/ESM module loaders fail on RapydScript's browser IIFE scoping.
   - *Logic*: `esbuild.config.mjs` was configured with an in-memory loader (`wanim-rapydscript-loader`) intercepting `rapydscript.js` with `loader: 'text'`. In `src/engine/rapydscriptInit.ts`, the text source is evaluated via `new Function('external_namespace', rapydscriptSource).call(globalThis, globalThis)` inside `ensureRapydscriptInitialized()`. Headless testing verified that `globalThis.RapydScript.compile` functions synchronously with zero external network requests.

4. **Namespace Isolation & Vim Cursor Precision**:
   - *Observation*: Un-scoped `.cm-fat-cursor` rules in the reference plugin bleed into all Obsidian notes.
   - *Logic*: In `styles.css`, every selector was scoped under `.wanim-block` or `.wanim-code-editor`. The Normal mode `#f10707` red block cursor was scoped to `.wanim-code-editor .cm-fat-cursor`, and the Insert mode thin white line cursor was scoped to `.wanim-code-editor .cm-cursor:not(.cm-fat-cursor)`.

5. **Architectural Code Principles (R5)**:
   - *Observation*: The user's code generation guidelines demand honest leaf functions, single level of abstraction ("stacking bricks"), invariant-rich types, and `{value}By{key}` map naming.
   - *Logic*: In `src/types.ts`, `resolvePluginSettings` is a pure leaf function with explicit parameters and return types. In `src/main.ts`, `broadcastEditorThemeChange` and `broadcastEditorVimChange` are pure leaf functions taking explicit collections. The plugin's active editor map is named `editorById`, and `onload()` reads as a uniform table of contents calling discrete brick methods.

## 3. Caveats

1. **Obsidian Runtime Injection**:
   - The Obsidian API (`obsidian`, `electron`, CM6 base packages) is provided dynamically by Obsidian at runtime. Headless tests outside Obsidian must provide a minimal mock for `obsidian.Plugin` to instantiate the plugin class.
2. **Dual-Plugin Code Block Tag**:
   - Both the reference plugin and Obsidian Wanim Plugin target the Markdown code block tag `'manim'`. During end-to-end testing in the Obsidian app in subsequent milestones, the reference plugin should be disabled in Obsidian Settings -> Community Plugins to avoid tag collision.
